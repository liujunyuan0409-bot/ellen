## 1. 为什么做 / 给谁用

一个企业飞书账号（下称「备份账号」）下有几千份云文档和上传文件，分散在「我的空间」、知识库、群聊里。需要：

1. 把这些文件**自动、定期**备份到本地电脑；
2. 文件在飞书上被改过，本地自动拉新版，**旧版不删**，按日期归档到同目录的「历史版本」文件夹；
3. 在线文档优先存 PDF，上传的原始资料保留原格式；
4. 查出「有哪些文件备份账号打不开」，列出数量和能拿到的名字线索。

**使用者（v0.2 新增）**
- 会有多个人使用，**都用同一个备份账号**；每个人在自己的电脑上各存一份完整备份，彼此不需要协调。实际上大概率只有一台电脑。
- 那台电脑**是 Mac 还是 Windows、装的是哪个 AI 工具，现在都不知道**。
- 使用者**没有开发背景**，第一次用的方式是：把本仓库的 GitHub 链接发给自己的 AI 助手，由 AI 完成本地安装、配置和第一次备份。之后日常由系统定时任务运行，不需要开着 AI 工具。

**关于「企业所有文件」**：飞书里每个成员的「我的空间」是私有的，超级管理员也无法读取别人未分享的文件。覆盖策略：
- **以共享位置为主**：公司工作文件统一放到备份账号可见的知识库 / 共享文件夹（团队规范，由人推动，不是程序功能），程序覆盖备份账号能看到的一切。
- **不做**每个员工各自授权；**不做**付费版审计（只能列清单、拿不到内容，免费版也不可用）。
- 权限缺口报告（§6.8）用来发现「还散落在别人私人空间、但在群里出现过」的文件。

## 2. 目标 / 非目标 / 反目标

**目标**
- 任意 AI 助手拿到仓库链接，都能按 `AGENTS.md` 带不懂技术的人完成：检查/安装 Python → 安装程序 → 7 步配置向导 → 第一次备份。
- macOS 和 Windows 行为一致：同样的目录结构、同样的报告、同样的「旧版永不删除」。
- 首次配置有向导：逐步指引、每步实测飞书接口、失败给出可操作的修复说明；备份目录在首次配置时询问。
- 每周一次增量备份（默认周一 12:00），错过则补跑；中断后可续跑；随时可手动触发。
- 每次运行产出一份人能读的报告；权限缺口清单。

**非目标**
- Linux；免安装打包版（PyInstaller 等，需签名，留待以后）。
- 多台电脑之间的协调或合并备份。
- 全企业空间盘点（免费版无审计日志接口）。
- 双向同步、往飞书回写；备份聊天文字、日历、邮件（群聊**附件**要备份）。
- 读取其他成员私人空间里未分享给备份账号的文件。

**反目标（做了就算失败）**
- 删除或覆盖任何本地旧版本文件。
- 对飞书做任何写操作（程序只用只读调用，见 §6.7）。
- 把 App Secret、token、备份清单、备份文件推进 git 仓库，或让 App Secret 经过 AI 对话。
- 静默失败：token 过期、备份盘没插、接口报错、定时任务失效时用户毫不知情。
- 某个 AI 工具因为说明写得只适合 Claude 而无法完成安装。

## 3. 已实测的事实（2026-11-13～15，备份账号）

| 项 | 结果 |
|---|---|
| 我的空间 | 5,436 个文件 / 412 个文件夹；5,318 个归备份账号所有；每个都有 `modified_time` |
| 知识库 | 12 个空间、310 个节点 |
| 导出 | docx→pdf、doc→pdf、sheet→xlsx、bitable→xlsx、slides→pdf 均可（幻灯片单份可达 40–67MB） |
| 上传文件下载 | 原格式；支持 `Range` 头 |
| 权限判断 | `GET /drive/v1/permissions/:token/members/auth?action=view` 可用 |
| 打不开的文件 | `metas/batch_query` **不返回标题和所有者** → 名字只能从聊天消息上下文推断 |
| 群消息 | 用户身份读取（需应用开启机器人能力）；318 个群（36 外部）；抽样 874 条消息 → 53 个文档链接，1 个无权限，5 个已删除/无效 |
| 搜索 | 可用，能发现部分「共享给我」文档；分页受上限约束（offset+count < 200） |
| 审计日志 | 免费版不可用 |
| 体积 | 上传文件 3,542 个 = **46.4 GB**（mov 20.0 GB、psd 14.1 GB…，单个最大 997 MB）；在线文档导出 ≈ 1 GB；**首次合计 ≈ 47–50 GB，不含群聊附件** |
| 冒烟（v0.1.0） | 体检 8/8 通过；扫描 5,664 项（与上面相差 1.4%）；试备份 20 个全部成功，再跑全部「未变化」 |
| **授权是累计的** | 程序只申请 24 项只读权限，但飞书会把该账号对该应用**历史上授过的所有权限**都放进令牌。要让令牌真正只读，需先在飞书里撤销该应用授权，再重新登录 |

飞书应用侧：一个企业自建应用，免审，可用范围仅备份账号，机器人能力已开，「允许被其他机器人邀请进群」已关，重定向 URL `http://127.0.0.1:8765/callback`。

## 4. 方案比较（v0.2 选定 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 一套 Python 程序 + 按系统替换的「平台零件」+ 通用 AI 说明（选定）** | 核心逻辑不变；定时、通知、密码弹窗、文件锁、路径规则各有 Mac / Windows 两份实现；安装说明写成任何 AI 都读得懂的 `AGENTS.md` | 已过 263 个测试和多轮审查的核心逻辑原样复用；只需 Python 3.9+，两个系统都能一条命令装上 |
| B. Windows 另写 PowerShell 脚本 | 两套代码 | 两套越改越不一致；已修的数据安全问题要重修一遍 |
| C. 打包成免安装程序 | PyInstaller 每系统打包 | Mac 无签名被 Gatekeeper 拦、Windows 弹 SmartScreen，不懂技术的人反而卡住；留待以后 |

v0.1.0 时比较过的 lark-cli、官方 Node CLI 方案仍不采用（内部构建装不到 / 多一套运行时）。

## 5. 用户看到的样子

### 5.1 第一次使用：把链接发给 AI

使用者对自己的 AI 助手说：「帮我装一下这个，备份我们公司的飞书文件：<GitHub 链接>」。

AI 读到仓库根目录的 `AGENTS.md`（Codex、Cursor、Gemini CLI 等会自动读；Claude Code 用户也可以 `/plugin install`，其 SKILL.md 指向同一份说明），按下面的顺序带用户走。**规则：一次只问一个问题；用大白话；任何一步 ✗ 就原样转述修复说明并停下。**

```
[0] 准备
    · 判断系统：macOS 还是 Windows
    · 检查 Python ≥ 3.9：
        macOS   没有 → 让用户运行 xcode-select --install（系统弹窗点「安装」）
        Windows 没有 → winget install Python.Python.3.12（AI 代为运行或指导用户运行）
    · 取得程序：git clone 本仓库到固定位置（macOS ~/feishu-backup，Windows %USERPROFILE%\feishu-backup）；
      没有 git 时下载仓库 zip 解压到同一位置
    · 运行 fbk 的 `install` 命令：把程序复制到稳定位置（见 §6.2），之后一律从那里运行
[1/7] 环境检查      Python 版本、能否连到 open.feishu.cn、证书是否正常
[2/7] 应用凭证      App ID / App Secret 由管理员私下发给使用者；系统弹窗输入（不经过 AI 对话）
                    → 实测换取应用令牌
[3/7] 登录授权      浏览器打开授权页 → 需要以「备份账号」身份点授权（扫码时需备份账号的手机配合）
                    → 实测读取用户信息，显示「已登录：<姓名>」
[4/7] 权限体检      8 项实测：列我的空间 / 列知识库 / 搜索 / 发起一次导出 / 读一个文件的 1 字节 /
                    权限判断 / 列群 / 读一条群消息
[5/7] 备份目录      询问放哪里；检查可写、剩余空间（建议 ≥ 100 GB）、是否在云同步目录（iCloud / OneDrive 警告）
[6/7] 首次扫描      只统计不下载：文件数、类型分布、预估体积和耗时 → **等用户明确确认**
[7/7] 定时任务      安装每周定时任务（默认周一 12:00）；显示下次运行时间和卸载方法；
                    询问是否现在就开始第一次备份（后台运行）
```

**写给 AI 的注意事项（放在 `AGENTS.md` 里）**
- 有的 AI 工具默认不允许联网或在工作区外写文件（例如 Codex 的沙箱）：遇到网络/权限错误时，先向用户申请放开权限，不要当成飞书故障。
- 「登录授权」和「第一次备份」耗时长：能后台运行就后台运行；不能后台运行的工具，告诉用户「这一步要等几分钟到几小时，窗口别关」，或指导用户在系统终端里运行。
- 弹窗（输入 App Secret）会等待最多 5 分钟：提醒用户留意弹出的窗口。
- **绝不在对话里索要、接收或复述 App Secret**；用户贴进来了就提醒其到开发者后台重置。
- 所有命令都有 `--json` 输出，便于 AI 读取结果；面向用户的说明用中文。

### 5.3 日常

- 不需要人管。出错、需要重新登录、定时任务失效、连续两周没备份成功时，弹系统通知（macOS 通知中心 / Windows 通知）。
- 对 AI 说「飞书备份状态」→ 上次成功时间、下次计划时间、失败清单、定时任务是否正常。
- 「现在备份一次」→ 立即运行（不受每周时间限制）。
- 「看权限缺口」→ 打开最新的 `_报告/*_权限缺口.csv` 并总结。
- 「把备份时间改成每周五晚上 8 点」→ 改配置并重装定时任务。

## 6. 设计细节

### 6.1 组件

| 文件 | 作用 |
|---|---|
| `AGENTS.md`（仓库根目录） | **通用 AI 安装与使用说明**：任何 AI 读了都能完成 §5.1；指向插件目录里的详细说明 |
| `plugins/feishu-backup/AGENTS.md` | 插件级详细说明（命令、每步怎么判断成功、常见报错怎么办、日常操作）——唯一的说明正本 |
| `plugins/feishu-backup/skills/feishu-backup/SKILL.md` | Claude Code 的触发入口；内容只做触发词 + 指向 AGENTS.md，避免两份说明分叉 |
| `.../scripts/fbk.py` | 唯一程序入口，子命令：`install` `setup` `doctor` `login` `scan` `run` `status` `perms` `schedule` |
| `.../scripts/fbk/`（核心，不随系统变化） | client、auth、store、walker、fetcher、sync、chats、perms、report、runner、wizard |
| `.../scripts/fbk/platform/`（**v0.2 新增**） | 按系统选择实现：`paths`（配置/日志/程序副本位置）、`scheduler`（launchd / 任务计划程序）、`notify`（osascript / PowerShell 通知）、`prompt`（osascript 对话框 / tkinter 对话框）、`lock`（fcntl.flock / msvcrt.locking）、`awake`（caffeinate / SetThreadExecutionState）、`fsnames`（文件名与路径规则） |
| `README.md` | 给人看的：这是什么、飞书后台准备、换电脑、卸载、局限 |

### 6.2 位置（本机，不进仓库）

| 用途 | macOS | Windows |
|---|---|---|
| 配置 `config.json`、令牌 `token.json`（仅本人可读） | `~/.config/feishu-backup/` | `%APPDATA%\feishu-backup\` |
| 日志（保留 30 天） | `~/Library/Logs/feishu-backup/` | `%LOCALAPPDATA%\feishu-backup\logs\` |
| 程序副本（定时任务从这里运行） | `~/Library/Application Support/feishu-backup/app/` | `%LOCALAPPDATA%\feishu-backup\app\` |

- 程序副本：`install` 和 `setup --schedule` 把 `scripts/` 整体复制过去（先复制到临时目录再改名）；插件或仓库更新后再运行一次即可；`status` / `doctor` 检查副本版本与路径。
- Windows 上令牌文件用 NTFS 默认的用户目录权限保护（`%APPDATA%` 只有本人可访问）。

### 6.3 调度：每周一次，错过补跑

- **计划**：配置 `schedule = {weekday: 1, time: "12:00"}`（周一中午 12 点，本机时区），可改。
- **触发方式（两个系统相同的思路）**：定时任务**每小时醒一次 + 登录/开机时运行一次**，由程序判断要不要真跑：
  - 「最近一个计划时间点」= 最近一次已经过去的「周一 12:00」；**上次成功完成早于这个时间点 → 该跑**，否则立即退出。
  - 这样周一中午电脑关着/睡着，下次开机或唤醒后的那个小时内会自动补跑；一周内不会重复跑。
  - 备份盘没插 → 记日志，每天最多提醒一次；没网 → 静默退出，下个小时再试；已有进程在跑 → 退出。
- **macOS**：LaunchAgent，`RunAtLoad` + `StartInterval=3600`，通过 `/usr/bin/caffeinate -i` 启动以防跑到一半进入闲置睡眠。
- **Windows**：任务计划程序（`schtasks /Create /XML`），触发器 = 用户登录时 + 每小时重复；`StartWhenAvailable=true`、`DisallowStartIfOnBatteries=false`、仅在用户登录时运行（不保存 Windows 密码）；用 `pythonw.exe` 运行，不弹黑色命令行窗口；运行期间调用 `SetThreadExecutionState` 防止睡眠。
- **没读全的重试节奏（实现者决定）**：某次运行有文件夹没读全（不算成功）时，下一次重试间隔 6 小时而不是 1 小时，直到成功，避免某个文件夹持续读取失败时每小时都扫一遍几千个文件。
- **备份盘没插的判断（已有行为，沿用）**：备份根目录不存在即视为「没插」，**程序绝不新建这个目录**（例如 Windows 的 `D:\` 盘不在时不会在别处建一棵空目录树）；只有向导里 `--create` 才会新建。
- **手动**：`run --now` 立即运行，不看计划时间。
- **版本粒度**：每周一次意味着「历史版本」是每周的快照，一周内改了多次只保留备份时的那一版；想要更密可以把计划改成每天，或随时手动触发。
- **过期提醒**：上次成功早于「两个计划时间点之前」（即连续错过两周）→ 每天最多提醒一次「飞书备份已经 N 天没有成功完成」。
- 首次全量可能跨好几次开机：每处理完一个文件就落盘清单，下次从断点继续；下载先写临时文件，完成后原子改名。

### 6.4 遍历范围（与 v0.1.0 相同）

1. 我的空间（递归）；2. 知识库（备份账号可见的全部空间；有子页面的文档存为 `标题.pdf`，子页面放进同名文件夹）；3. 快捷方式（解析到目标，指向文件夹的递归备份）；4. 共享给我（群聊链接 + 搜索发现、能打开但不在 1–3 中的文档，一发现就记入清单，失败的每次重试，之后有更新也会拉新版）；5. 群聊附件（文件和音视频，**不含图片**）。
单个文件夹/空间读取失败不中断整次运行；这次没读全时不标记任何文件为「云端已删除」，且这次不算成功（下个小时重试）。

### 6.4.1 去重（与 v0.1.0 相同）

同一云端对象多处出现只存一份（我的空间 > 知识库 > 共享给我）；附件与上传文件按内容哈希去重；在线文档以飞书修改时间判断是否有改动。

### 6.5 格式规则（与 v0.1.0 相同）

文档 / 幻灯片 → PDF；表格 / 多维表格 → xlsx；上传文件与群聊附件 → 原格式；无导出接口的类型（思维笔记等）→ 跳过并在报告中列出。

### 6.6 增量、历史版本、文件名

- 新文件 → 下载/导出；飞书上改过 → 新版先下到临时文件，成功后把旧版移入同目录 `历史版本/原名_YYYY-MM-DD_HHMM.扩展名`（旧版的飞书修改时间，北京时间），再放入新版；云端改名/移动 → 本地跟着改，历史版本一起搬；云端删除或失去权限 → **本地一律不删**。
- 清单里的本地路径存**相对于备份根目录**的路径（v0.1.0 终审修复），备份目录整体拷贝到别处/别的电脑后直接续上。
- **文件名规则（v0.2 统一为两系统都合法的写法，在两个系统上产生相同的名字）**：
  - 替换 `/ \ : * ? " < > |` 和控制字符为 `_`；去掉结尾的空格和点；
  - Windows 保留名（`CON` `PRN` `AUX` `NUL` `COM1–9` `LPT1–9`，不区分大小写、含扩展名时也算）加前缀 `_`；
  - 单个名字不超过 255 字节（UTF-8）；同目录同名（**不区分大小写**比较，适配 macOS/Windows 默认文件系统）→ 追加 ` (token 前 6 位)`。
- **Windows 长路径**：所有文件操作在 Windows 上使用 `\\?\` 前缀的绝对路径，绕过 260 字符限制；同时在向导第 5 步建议把备份根目录放在浅层路径（如 `D:\飞书备份`）。

### 6.7 只读与权限

- 程序的 HTTP 客户端内置白名单，只允许读取类请求（查询、下载、导出、搜索、查元数据、登录续期），其他请求发出前就被拦下。
- 登录时只申请实际用到的 24 项只读权限。注意 §3「授权是累计的」：若该账号以前对该应用授过更多权限，令牌仍会带上；README 说明如何撤销后重新登录以得到真正只读的令牌。

### 6.8 权限缺口报告、6.9 运行报告、6.10 限流与重试（与 v0.1.0 相同）

- 权限缺口 CSV（Excel 直接打开）：状态（能打开 / 无权限 / 已删除或无效 / 待重试）、类型、链接、文件名线索、分享人、群名、分享时间、首次发现日期；顶部汇总与局限说明。
- 运行报告每次一份（`YYYY-MM-DD_HHMM_备份日志.md`）。
- 每秒最多 5 次请求，导出并发 ≤ 3、下载并发 ≤ 4；限流或 5xx 自动重试；网络断开按离线处理（不算成功，下个小时重试）；令牌失效 → 停止并通知重新登录；失败的文件只在「失败名单变化时」通知。

### 6.11 v0.1.0 遗留的两个小问题（v0.2 修复）

1. **旧备份目录路径里恰好含「我的空间 / 知识库 / 共享给我 / 群聊附件」字样时**，迁移旧清单会截错位置，导致个别文件重下一份。修法：优先按记录下来的旧根目录精确截取；没有记录时依次尝试各个截断点，选能在新根目录下找到文件的那个。
2. **更新程序副本时**，两次改名之间有极短的瞬间程序目录不存在，若正好赶上定时触发会失败一次；正在运行的旧副本目录也可能被删掉。修法：副本改为按版本分目录（`app/<版本号>/`）+ 一个指向当前版本的小文件，定时任务启动器读这个指针；旧版本目录等没有进程使用后再清理。

### 6.12 其他实现者决定（已注明）

- **多台电脑**：每台电脑各自走一遍登录授权，各自保存令牌，不共享 `token.json`。若某台电脑的令牌因另一台登录而失效，按现有逻辑通知「需要重新登录」（实现时实测飞书是否会让旧令牌失效，结论写进 README）。
- **从 v0.1.0 升级**：v0.1.0 没有在任何电脑上装过定时任务，不写迁移代码；`schedule install` 会覆盖同名旧任务；旧配置里没有 `schedule` 字段时取默认（周一 12:00）。
- **仓库根目录 `AGENTS.md`**：本仓库含多个插件，根文件只写「本仓库有哪些插件、各自的说明在哪」，飞书备份的安装流程放在 `plugins/feishu-backup/AGENTS.md`，不影响其他插件。
- **Windows 部分的可测性**：定时任务 XML、路径转换、文件名规则、锁等都写成可在 macOS 上单元测试的纯函数或可注入的接口；另附一份「Windows 真机验收清单」。
- **Windows 版未经真机验证（2026-11-15 定）**：目前没有 Windows 电脑可测，README、`AGENTS.md`、CHANGELOG 和 `doctor` 在 Windows 上运行时都明确标注「Windows 版未经真机验证」，并给出验收清单路径；等那台电脑确定后按清单验证，再去掉标注。
