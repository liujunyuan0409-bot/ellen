# 飞书文件自动备份 skill · 设计文档

日期：2026-11-13　状态：草稿，待 Ellen 审阅
插件位置：本仓库 `plugins/feishu-backup/`（本仓库是 **public**，任何凭证、企业域名、备份数据都不进仓）

---

## 1. 为什么做 / 给谁用

Ellen 管理一个企业飞书账号（下称「备份账号」），账号下有几千份云文档和上传文件，分散在「我的空间」、知识库、群聊分享中。她要：

1. 把这些文件**自动、定期**备份到本地；
2. 文件在飞书上被改过，本地自动拉新版，**旧版不删**，按日期归档到同目录的「历史版本」文件夹；
3. 在线文档优先存 PDF，上传的原始资料保留原格式；
4. 查出「有哪些文件备份账号打不开」，列出数量和能拿到的名字线索。

**关于「企业所有文件」**：飞书里每个成员的「我的空间」是私有的，超级管理员也无法通过接口或网页读取别人未分享的文件。Ellen 选定的覆盖策略（2026-11-13）：
- **以共享位置为主**：公司工作文件统一放到备份账号可见的知识库 / 共享文件夹（这是团队规范，由 Ellen 推动，不是程序功能），程序自动覆盖备份账号能看到的一切。
- **不做**「每个员工各自授权」（会触及员工私人空间，Ellen 已否决）。
- **不做**付费版审计（只能列清单、拿不到内容，且免费版不可用）。
- 权限缺口报告（§6.8）用来发现「还散落在别人私人空间、但在群里出现过」的文件，作为推动收拢的依据。

运行环境：**另一台 Mac**，不常开机。以 Claude Code 插件形式分发，`git clone` / `/plugin install` 后按向导配置即可用；日常由系统定时任务运行，不依赖 Claude Code 开着。

## 2. 目标 / 非目标 / 反目标

**目标**
- 首次配置有交互式向导：逐步指引、每步实测飞书接口、失败给出可操作的修复说明。
- 备份目录在首次配置时询问。
- 增量备份：只下载有变化的文件；中断后可续跑。
- Mac 不常开机：开机/唤醒后自动判断是否该补跑。
- 每次运行产出一份人能读的报告（新增 / 更新 / 失败 / 跳过）。
- 权限缺口清单（需求 6）：列出打不开的文件 + 线索。

**非目标**
- 不做「全企业空间」盘点：免费版飞书不提供行为审计日志接口（2026-11-13 实测：权限目录里无 `admin:audit_info:readonly`，管理后台成员行为审计需升级套餐）。若将来升级套餐，再作为扩展。
- 不做 Windows / Linux 支持。
- 不做双向同步、不往飞书回写任何东西。
- 不备份聊天消息文字本身、日历、邮件（群聊里的**附件**要备份，见 §6.4）。
- 不读取其他成员私人空间里未分享给备份账号的文件。

**反目标（做了就算失败）**
- 删除或覆盖任何本地旧版本文件。
- 对飞书做任何写操作（应用虽开了读写权限，程序只用只读调用，见 §6.7）。
- 把 App Secret、token、备份清单、备份文件推进 git 仓库。
- 静默失败：token 过期、备份盘没插、接口报错时用户毫不知情。

## 3. 已实测的事实（2026-11-13，备份账号）

| 项 | 结果 |
|---|---|
| 我的空间 | 5,436 个文件 / 412 个文件夹；docx 1330、doc 52、sheet 361、bitable 27、slides 2、mindnote 14、shortcut 125、上传文件 3525；5,318 个归备份账号所有；每个都有 `modified_time` |
| 知识库 | 12 个空间、310 个节点（docx 231、sheet 58、file 17、bitable 2、slides 1、mindnote 1） |
| 导出 | docx→pdf ✅ doc→pdf ✅ sheet→xlsx ✅ bitable→xlsx ✅ slides→pdf ✅（单份可达 40–67MB） |
| 上传文件下载 | ✅ 原格式；支持 `Range` 头 |
| 权限判断 | `GET /drive/v1/permissions/:token/members/auth?action=view` ✅ |
| 打不开的文件的元数据 | `metas/batch_query` **不返回标题和所有者** → 名字只能从聊天消息上下文推断 |
| 群消息扫描 | **用户身份**（user token + `im:message.group_msg:get_as_user`）读取，机器人不需要进群；318 个群（36 外部）全部可列；抽 30 群×50 条 = 874 条消息 → 53 个文档链接，1 个无权限，5 个已删除/无效 |
| 搜索接口 | `search_key=""` 可用，返回 87 条；能发现部分「共享给我」文档 |
| 审计日志 | ❌ 免费版不可用 |
| 体积（只统计不下载） | 我的空间+知识库共 5,746 项。**上传文件 3,542 个 = 46.4 GB（精确）**，其中 mov 20.0 GB/222 个、psd 14.1 GB/196 个、pdf 3.8 GB、key 2.0 GB、ai 1.8 GB；单个最大 997 MB。在线文档导出估算（每类抽 8 份）：docx 1,561 份 ≈ 0.6 GB、sheet 419 ≈ 0.3 GB、slides 3 ≈ 0.1 GB、doc/bitable 可忽略 —— 抽样少，实际可能偏差数倍，但量级小。**首次合计 ≈ 47–50 GB，不含群聊附件**。文件夹最深 9 层 |

飞书应用侧已就绪：企业自建应用「福娃的飞书CLI」，免审，可用范围仅备份账号，机器人能力已开（读群消息必需），重定向 URL `http://127.0.0.1:8765/callback`，用户身份权限 120 项（含读写）。

## 4. 方案比较（已选 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. Python 标准库单脚本 + launchd（选定）** | 一个 `fbk.py`，只用 Python 标准库直接调飞书 OpenAPI；macOS LaunchAgent 定时触发 | 新 Mac 只需系统自带/brew 的 python3，零第三方依赖；完全可控（导出轮询、断点续跑、限流） |
| B. 基于 lark-cli | 复用现有 CLI | 本机那份是 Klook 内部构建，新 Mac 装不到；一次只能挂一个应用 |
| C. 基于官方开源 `larksuite/cli`（npm） | 依赖 Node + 官方 CLI | 多一套运行时；导出/下载/增量逻辑仍要自己写，CLI 只省了 HTTP 调用这一薄层 |

## 6. 设计细节

### 6.1 组件

| 文件 | 作用 |
|---|---|
| `plugins/feishu-backup/.claude-plugin/plugin.json` | 插件元数据 |
| `plugins/feishu-backup/skills/feishu-backup/SKILL.md` | 告诉 Claude：何时触发、如何走向导、如何解读报告和排障 |
| `.../scripts/fbk.py` | 唯一程序入口，子命令：`setup` `doctor` `login` `scan` `run` `status` `perms` `schedule install/uninstall` |
| `.../scripts/fbk/`（若单文件过大再拆） | client（HTTP+限流+重试+只读白名单）、auth、walker、exporter、store、report、launchd |
| `.../tests/` | 本地纯函数测试（命名、路径冲突、版本归档、清单迁移），不打真接口 |
| `README.md` | 安装、飞书后台前置配置（建应用/权限清单/重定向 URL/机器人）、换电脑步骤 |

### 6.2 配置与凭证（本机，不进仓）

- `~/.config/feishu-backup/config.json`（0600）：`app_id`、`app_secret`、`backup_root`、`interval_hours`（默认 24）。
- `~/.config/feishu-backup/token.json`（0600）：user access/refresh token。access 2 小时，程序自动续期。
- 日志：`~/Library/Logs/feishu-backup/`，按天滚动，保留 30 天。
- 换电脑：在新 Mac 跑向导即可；可选「从旧 Mac 拷 config.json」省去第 2 步。

### 6.3 调度（Mac 不常开机）

- LaunchAgent：`RunAtLoad` + `StartInterval=3600`（每小时醒一次），程序自己判断要不要真跑：
  - 距上次**成功**完成 < `interval_hours` → 立即退出；
  - 备份目录不存在（外接盘没插）→ 记日志，每天最多弹一次通知，退出；
  - 无网络 → 静默退出，下个小时再试；
  - 已有进程在跑（`run.lock` 含 PID 且进程存活）→ 退出。
- 首次全量可能跨好几次开机：每处理完一个文件就落盘清单，下次从断点继续。
- 合盖睡眠中断：下载写到 `*.part` 临时文件，完成后原子改名；重启时清理残留 `.part`。

### 6.4 遍历范围

1. **我的空间**：从根文件夹递归。
2. **知识库**：备份账号可见的所有空间，按节点树递归；有子节点的文档节点 → 文档存为 `标题.pdf`，子节点放进同名文件夹 `标题/`。
3. **快捷方式（shortcut）**：解析到目标；目标已在 1/2 范围内就跳过，否则按目标备份到快捷方式所在位置。
4. **共享给我**（Ellen 确认要备份）：来源 = 群聊链接扫描 + 搜索接口结果中，备份账号**能打开**、但不在 1–3 中的文档，存到 `共享给我/`（按发现来源分子目录：`共享给我/<群名>/`，搜索发现的放 `共享给我/_搜索发现/`）。
5. **群聊附件**（Ellen 确认要备份）：备份账号所在全部群里，消息类型为**文件**（`file`）和**音视频**（`audio` / `media`）的附件，用消息资源下载接口（`GET /im/v1/messages/:message_id/resources/:file_key`）按原格式保存到 `群聊附件/<群名>/`，文件名 `YYYY-MM-DD_原文件名`。**图片消息（`image`）及富文本里内嵌的图片不备份**（Ellen 2026-11-13 决定）。与权限缺口扫描共用同一遍消息遍历和「每群已扫到的位置」游标。首次回溯范围与 §6.8 相同。

### 6.4.1 去重（Ellen 要求：完全一样的文件不重复保存）

- **同一个云端对象**（同一 token）出现在多个位置（快捷方式、多个群里转发了同一个链接）→ 只存一份，存在第一个发现的位置（优先级：我的空间 > 知识库 > 共享给我）；其他位置不再落盘，清单里记录「另见」。
- **群聊附件**按内容 SHA-256 去重：同样内容已存在（任何群、任何位置的附件或上传文件）→ 不再存，清单记录引用。
- **更新判断**：上传文件和附件以内容哈希为准，下载后与本地相同则不归档、不覆盖；在线文档以飞书 `modified_time` 为准（同一文档每次导出的 PDF 字节可能不同，逐字节比较不可靠）。

### 6.5 格式规则

| 飞书类型 | 本地格式 |
|---|---|
| docx / doc（文档） | PDF |
| slides（幻灯片） | PDF |
| sheet（电子表格） | xlsx（飞书不支持表格导 PDF） |
| bitable（多维表格） | xlsx |
| file（上传的文件） | 原文件原格式，不转换 |
| mindnote / 其他 | 若无导出接口则跳过，在报告「跳过」节列出 |

> 需求原文是「优先导出 PDF，如果是其他人上传的资料则保留原格式」。本设计理解为：**在线文档 → PDF，所有上传的文件 → 原格式**（不区分上传人）。理由：上传文件本身就是原始资料，转 PDF 会丢信息；且大部分上传文件归备份账号所有，按上传人区分没有实际差别。—— Ellen 已确认（2026-11-13）。

### 6.6 增量与历史版本

清单 `manifest.sqlite` 每个云端对象一行：`token, type, source, remote_path, remote_modified_time, local_path, local_ext, last_backup_at, status`。

每次运行：
- **新文件** → 下载/导出到对应路径。
- **`modified_time` 变了** →
  1. 把当前本地文件移到同目录 `历史版本/`，改名为 `原名_YYYY-MM-DD_HHMM.扩展名`，时间取**旧版本的飞书修改时间**（北京时间）；重名追加 `-2`、`-3`；
  2. 下载新版到原路径。
- **云端改名 / 移动** → 本地当前文件同步改名/移动（不算新版本）；该文件已有的历史版本跟着移到新位置的 `历史版本/`。
- **云端删除 / 备份账号失去权限** → **本地一律不删**；清单标记 `remote_deleted` / `access_lost`，报告里列出。
- **文件名清洗**：`/ : \` 等非法字符替换为 `_`；同目录同名 → 追加 ` (token 前 6 位)`；文件名超长截断保留扩展名。

**版本粒度（实现者决定，已注明）**：版本 = 每次运行时的快照。两次运行之间被改了多次，只留运行时那一版。飞书的「文档版本」接口只覆盖用户手动创建的命名版本，覆盖不了每一次编辑，所以不去拉。如果需要更密的快照，把 `interval_hours` 调小即可。

**磁盘空间（实现者决定，已注明）**：每个文件写入前检查剩余空间。剩余空间低于「该文件预估大小 + 2GB」时，**中止本次运行**并弹通知「备份盘空间不足」，已完成的部分保留，下次从断点续跑。不对历史版本设数量上限（反目标：不删旧版本）。向导第 5 步按「首次体积 × 1.5」给出容量建议。

### 6.7 安全：只读白名单

应用开了读写权限（Ellen 的要求），但程序的 HTTP 客户端内置**白名单**，只允许：
`GET` 任意（含消息资源下载） · `POST /drive/v1/export_tasks` · `POST /suite/docs-api/search/object` · `POST /drive/v1/metas/batch_query` · OAuth/token 端点。
其他任何写方法/路径直接抛异常，不发请求。单测覆盖这条。

### 6.8 权限缺口报告（需求 6）

- 每次运行增量扫描全部群（每群记录已扫到的最新消息时间，下次只扫之后的）；首次扫描回溯范围默认 180 天（可配）。
- 抽出所有飞书文档链接，去重后逐个判断：可读 / **无权限** / 已删除或无效。
- `_报告/YYYY-MM-DD_权限缺口.csv`（UTF-8 BOM，Excel 直接打开）列：
  `状态, 类型, 链接, 文件名线索(消息原文中的标题/卡片标题), 分享人, 群名, 分享时间, 首次发现日期`
- 报告顶部汇总：共发现 N 个链接，无权限 X 个，已删除 Y 个。
- 明确写进报告的局限说明：只能发现「出现在备份账号所在群里」或「搜索得到」的文件；全企业盘点需付费版审计日志。

### 6.9 运行报告

`_报告/YYYY-MM-DD_备份日志.md`：本次耗时、新增/更新/改名/失败/跳过各多少，失败与跳过逐条列出原因；历史版本归档了哪些。

### 6.10 限流与重试

- 全局请求速率上限（默认 5 次/秒），导出任务并发 ≤ 3，下载并发 ≤ 4。
- 429 / 5xx 指数退避重试 5 次；单文件失败不影响整体，记入失败清单，下次运行重试。
- refresh token 失效 → 停止、弹通知「需要重新登录：对 Claude 说『飞书备份重新登录』」。
