飞书文件自动备份 skill

把企业飞书里能看到的文件每周备份到本地电脑，改过的文件自动拉新版、旧版按日期归档，并列出打不开的文件。不管是 Mac 还是 Windows、用哪个 AI 助手，把链接发给 AI 就能装好。

§1

为什么做、给谁用

一个企业飞书账号（下称备份账号）下有几千份云文档和上传文件，分散在「我的空间」、知识库和群聊里。需要做到：

  1. 把这些文件自动、定期备份到本地电脑；
  2. 文件在飞书上被改过，本地自动拉新版，旧版不删，按日期归档到同目录的「历史版本」文件夹；
  3. 在线文档优先存 PDF，上传的原始资料保留原格式；
  4. 查出备份账号打不开的文件，列出数量和能拿到的名字线索。

谁在用v0.2

  • 会有多个人用，都用同一个备份账号，每人在自己电脑上各存一份完整备份，彼此不用协调。实际上大概率只有一台电脑。
  • 那台电脑是 Mac 还是 Windows、装的是哪个 AI 工具，现在都不知道。
  • 使用的人没有开发背景：把 GitHub 链接发给自己的 AI 助手，由 AI 完成安装、配置和第一次备份。之后由系统定时运行，不用开着 AI。

关于「企业所有文件」

飞书里每个成员的「我的空间」是私有的，超级管理员也读不到别人没分享的文件。所以：

  • 以共享位置为主：公司工作文件统一放到备份账号能看到的知识库或共享文件夹（团队规范，需要人推动）。
  • 不做每个员工各自授权；不做付费版审计。
  • 权限缺口报告用来找出还散落在别人私人空间、但在群里出现过的文件。
§2

目标与边界

目标

  • 任何 AI 助手拿到链接，都能带不懂技术的人装好并完成第一次备份
  • Mac 和 Windows 行为一致，旧版都永不删除
  • 配置向导逐步实测，失败给出修法
  • 每周一次增量备份，错过补跑，可手动触发
  • 每次运行一份报告，加权限缺口清单

不做

  • Linux；免安装打包版（以后再说）
  • 多台电脑之间协调或合并
  • 全企业空间盘点（免费版没有接口）
  • 双向同步；备份聊天文字、日历、邮件
  • 读别人私人空间里没分享的文件

做了就算失败

  • 删除或覆盖本地任何旧版本
  • 对飞书做任何写操作
  • 密钥、令牌、备份进 git，或 App Secret 经过 AI 对话
  • 静默失败：出问题了没人知道
  • 说明只适合 Claude，换个 AI 就装不上

§5

用起来的样子

第一次使用：把链接发给 AI

使用的人对自己的 AI 助手说：「帮我装一下这个，备份我们公司的飞书文件：<GitHub 链接>」。AI 读到仓库里的 AGENTS.md，按下面的顺序带着走。一次只问一个问题，用大白话，任何一步出错就照实转述修法并停下。

  1. 0
    准备判断是 Mac 还是 Windows；检查 Python 3.9 以上：Mac 没有就运行 xcode-select --install，Windows 没有就用 winget install Python.Python.3.12；把程序下载到固定位置（Mac ~/feishu-backup，Windows %USERPROFILE%\feishu-backup）；运行 install 把程序复制到稳定位置
  2. 1/7
    环境检查Python 版本、能否连到飞书、证书是否正常
  3. 2/7
    应用凭证App ID 和 App Secret 由管理员私下发给使用者，在系统弹窗里输入，不经过 AI 对话；实测能否换到应用令牌
  4. 3/7
    登录授权浏览器打开授权页，以备份账号身份点「授权」（扫码时需要备份账号的手机配合）；显示「已登录：姓名」
  5. 4/7
    权限体检8 项实测：列我的空间、列知识库、搜索、发起一次导出、读一个文件的 1 字节、权限判断、列群、读一条群消息
  6. 5/7
    备份目录询问放哪里；检查能否写入、剩余空间、是否在 iCloud / OneDrive 同步目录里
  7. 6/7
    首次扫描只统计不下载：文件数、类型、预估体积和耗时。等用户确认后才开始
  8. 7/7
    定时任务安装每周定时（默认周一 12:00），显示下次运行时间和卸载方法；询问是否现在就开始第一次备份

写给 AI 的注意事项

  • 有的 AI 工具默认不让联网或在工作区外写文件（例如 Codex 的沙箱）：遇到网络或权限错误，先向用户申请放开，不要当成飞书故障。
  • 登录和第一次备份耗时长：能后台运行就后台运行；不能的话告诉用户窗口别关，或指导在系统终端里运行。
  • 输入 App Secret 的弹窗最多等 5 分钟，提醒用户留意。
  • 绝不在对话里索要、接收或复述 App Secret；用户贴进来了，就提醒去后台重置。

日常

  • 不用管。出错、需要重新登录、定时任务失效、连续两周没备份成功时，弹系统通知。
  • 说「飞书备份状态」：上次成功时间、下次计划时间、失败清单、定时任务是否正常。
  • 说「现在备份一次」：立即运行，不受每周时间限制。
  • 说「看权限缺口」：打开最新的缺口清单并总结。
  • 说「把备份时间改成每周五晚上 8 点」：改好并重装定时任务。

设计细节

6.1 组件

文件作用
AGENTS.md（仓库根目录）通用 AI 安装说明入口，指向插件里的详细说明
plugins/feishu-backup/AGENTS.md详细说明的唯一正本：命令、每步怎么判断成功、常见报错、日常操作
SKILL.mdClaude Code 的触发入口，只放触发词并指向 AGENTS.md，避免两份说明不一致
scripts/fbk.py唯一程序入口：install setup doctor login scan run status perms schedule
fbk/ 核心遍历、同步、归档、去重、报告等，不随系统变化
fbk/platform/新按系统选实现：位置、定时、通知、密码弹窗、文件锁、防睡眠、文件名规则

macOS

  • 定时：launchd，每小时检查 + 登录时运行，用 caffeinate 防睡眠
  • 通知：系统通知中心
  • 密码弹窗：系统对话框
  • 配置：~/.config/feishu-backup/
  • 程序副本：~/Library/Application Support/feishu-backup/app/

Windows

  • 定时：任务计划程序，每小时检查 + 登录时运行，错过后可用时补跑，不弹黑窗口，运行时防睡眠
  • 通知：Windows 通知
  • 密码弹窗：Python 自带窗口（不可用时改用 PowerShell）
  • 配置：%APPDATA%\feishu-backup\
  • 程序副本：%LOCALAPPDATA%\feishu-backup\app\

6.3 调度：每周一次，错过补跑

  • 计划时间默认每周一 12:00（本机时区），可改。
  • 定时任务每小时醒一次、开机登录时也运行一次，由程序判断：上次成功早于「最近一个已过去的周一 12:00」就跑，否则退出。周一中午电脑关着，开机后一小时内补上；一周内不会重复跑。
  • 备份盘没插：每天最多提醒一次。没网：下个小时再试。已有一个在跑：退出。
  • 某次有文件夹没读全：6 小时后再试，直到成功，不会每小时都扫一遍。
  • 备份目录不存在就当作「盘没插」，绝不自己新建，避免在别处建出一棵空目录。
  • 手动「现在备份一次」：立即运行。
  • 每周一次意味着历史版本是每周的快照：一周内改了几次，只留备份时那一版。想更密可以改成每天，或随时手动触发。
  • 连续错过两周：每天最多提醒一次「已经 N 天没有成功备份」。
  • 首次全量可能跨好几次开机，每完成一个文件就记一笔，下次从断点继续。

6.4–6.5 范围、去重、格式（与 v0.1.0 相同）

  • 范围：我的空间、知识库、快捷方式（含指向文件夹的）、共享给我、群聊附件（文件和音视频，不含图片）。
  • 一个文件夹读取失败不中断整次运行；没读全的那次不把任何文件标成「已删除」，也不算成功。
  • 同一文件多处出现只存一份；内容完全相同的只存一份。
  • 文档、幻灯片存 PDF；表格、多维表格存 xlsx；上传文件和附件保持原格式。

6.6 历史版本与文件名

  • 飞书上改过：新版先下到临时文件，成功后把旧版移到同目录 历史版本/原名_YYYY-MM-DD_HHMM，再放入新版。云端删了：本地一律不删。
  • 清单存相对路径，备份文件夹拷到别处或别的电脑能直接续上。
  • 文件名统一用两个系统都合法的写法v0.2：/ \ : * ? " < > | 换成 _；去掉结尾空格和点；CON、NUL 等 Windows 保留名前面加 _；同名判断不区分大小写，重名时加上编号后缀。
  • Windows 长路径：文件操作用 \\?\ 前缀绕过 260 字符限制；向导建议把备份目录放在浅层，例如 D:\飞书备份。

6.7 只读与权限

程序内置白名单，只允许读取类请求；登录只申请 24 项只读权限。因为授权是累计的，README 写明如何撤销授权后重新登录，得到真正只读的令牌。

6.8–6.10 报告与重试（与 v0.1.0 相同）

  • 权限缺口表：能打开 / 无权限 / 已删除或无效 / 待重试，附分享人、群名、时间。
  • 运行报告每次一份：日期_时间_备份日志.md。
  • 限流和出错自动重试；断网算离线，下个小时重试；登录失效通知重新登录；失败名单变化时才通知。

6.11 修掉的两个小问题v0.2

  1. 旧备份目录的路径里恰好带「知识库」等字样时，迁移会截错位置，个别文件多下一份。改为优先按记录的旧目录精确截取，否则逐个尝试，选能找到文件的那个。
  2. 更新程序副本的一瞬间，定时任务可能失败一次，正在运行的旧副本也可能被删。改为按版本分目录存放，加一个指向当前版本的小文件，旧版本等没人用了再清理。
§6.12

其他已定的做法

  • 多台电脑：每台各自登录一次，不共用登录令牌；某台令牌失效就提醒重新登录。
  • 从 v0.1.0 升级：v0.1.0 没在任何电脑上装过定时任务，不需要迁移；旧配置没有每周设置时，默认周一 12:00。
  • 仓库根目录的 AGENTS.md：只写「有哪些插件、说明在哪」，不影响仓库里其他插件。
  • Windows 部分：都写成能在 Mac 上自动测试的形式，另附一份 Windows 真机验收清单。
  • Windows 版未经真机验证：现在没有 Windows 电脑可测，说明文档、更新记录，以及在 Windows 上运行体检时都会明确标注这一点，并给出验收清单；等电脑确定后按清单验完再去掉。
§7

留给开发时确认

  • Windows 通知不装额外模块能否弹出；弹不出就只写日志。
  • Windows 上 Python 自带的弹窗是否可用；不可用改用 PowerShell。
  • 任务计划程序的最小配置，以及「仅登录时运行」下的稳定性。
  • Codex、Cursor、Gemini CLI 等读取 AGENTS.md 的方式和沙箱限制。
  • Windows 长路径与大小写不敏感在去重、重名判断里的处理。
  • 思维笔记能否导出；登录续期能撑多久不开机。
