飞书文件自动备份 skill

把企业飞书里能看到的文件定期备份到另一台 Mac，改过的文件自动拉新版、旧版按日期归档，并列出打不开的文件。

草稿 · 待审阅

§1

为什么做、给谁用

一个企业飞书账号（下称备份账号）下有几千份云文档和上传文件，分散在「我的空间」、知识库和群聊里。需要做到：

  1. 把这些文件自动、定期备份到本地；
  2. 文件在飞书上被改过，本地自动拉新版，旧版不删，按日期归档到同目录的「历史版本」文件夹；
  3. 在线文档优先存 PDF，上传的原始资料保留原格式；
  4. 查出备份账号打不开的文件，列出数量和能拿到的名字线索。

关于「企业所有文件」

飞书里每个成员的「我的空间」是私有的，超级管理员也无法通过接口或网页读取别人没分享的文件。选定的覆盖策略：

  • 以共享位置为主：公司工作文件统一放到备份账号能看到的知识库或共享文件夹。这是团队规范，需要人推动，程序负责备份备份账号能看到的一切。
  • 不做每个员工各自授权（会触及员工私人空间）。
  • 不做付费版审计（只能列清单、拿不到内容，免费版也不可用）。
  • 权限缺口报告（§6.8）用来找出还散落在别人私人空间、但在群里出现过的文件，作为推动收拢的依据。

运行环境：另一台 Mac，不常开机。以 Claude Code 插件分发，装好后按向导配置；日常由系统定时任务运行，不需要开着 Claude Code。

§2

目标与边界

目标

  • 首次配置有向导：逐步指引，每步实测飞书接口，失败给出修复方法
  • 首次配置时询问备份目录
  • 增量备份，中断后可续跑
  • 开机或唤醒后自动判断是否该补跑
  • 每次运行出一份能读的报告
  • 权限缺口清单

不做

  • 全企业空间盘点（免费版没有审计日志接口）
  • Windows / Linux
  • 双向同步、往飞书回写
  • 聊天文字、日历、邮件（群里的附件要备份）
  • 读取别人私人空间里没分享的文件

做了就算失败

  • 删除或覆盖本地任何旧版本
  • 对飞书做任何写操作
  • 把密钥、令牌、清单、备份文件推进 git 仓库
  • 静默失败：令牌过期、盘没插、接口报错时没人知道

§4

方案选择

方案做法取舍
选定 A. Python 单脚本 + 系统定时一个 fbk.py，只用 Python 标准库直接调飞书接口；macOS 定时任务触发新 Mac 只要有 python3，不用装任何依赖；导出、续跑、限流全部可控
B. 基于 lark-cli复用现有命令行工具本机那份是公司内部版本，新 Mac 装不到；一次只能挂一个应用
C. 飞书官方开源 CLI依赖 Node + 官方 CLI多一套运行环境；导出、下载、增量逻辑还得自己写
§5

用起来的样子

安装与首次配置向导

在新 Mac 上安装插件后，对 Claude 说「配置飞书备份」。向导共 7 步，每步都实测，失败就停在这一步并告诉你怎么修。

  1. 1/7
    环境检查python3 版本够不够，网络能不能连到飞书
  2. 2/7
    应用凭证输入 App ID 和 App Secret，附带去开发者后台哪里找。实测能否换到应用令牌
    常见失败：Secret 填错、应用被停用 → 给出后台链接和检查项
  3. 3/7
    登录授权自动打开浏览器，用备份账号点「授权」。实测读取用户信息，显示「已登录：姓名」
    常见失败：回调地址没配、端口被占、缺权限 → 列出缺哪几项
  4. 4/7
    权限体检逐项实测：列我的空间、列知识库、搜索、导出一份文档、下载一个文件的 1 字节、权限判断、列群、读一条群消息。每项打 ✓ 或 ✗，✗ 写明原因和修法
  5. 5/7
    备份目录询问放在哪里（建议外接盘或 ~/飞书备份）。检查能否写入、剩余空间够不够、是否在 iCloud 同步目录里
  6. 6/7
    首次扫描只统计不下载：文件数、类型分布、预估体积和耗时。确认后才开始首次全量
  7. 7/7
    定时任务安装系统定时任务，显示下次检查时间和卸载方法

向导可以重复运行，只重做失败或指定的步骤。日常排障单独跑第 4 步体检即可（fbk.py doctor）。

§6

设计细节

6.1 组件

文件作用
SKILL.md告诉 Claude 何时触发、怎么走向导、怎么解读报告和排障
scripts/fbk.py唯一程序入口：setup doctor login scan run status perms schedule
tests/本地测试：命名、路径冲突、版本归档、只读白名单，不调真接口
README.md安装、飞书后台前置配置、换电脑步骤

6.2 配置与凭证（只在本机，不进仓库）

  • ~/.config/feishu-backup/config.json：App ID、Secret、备份目录、备份间隔（默认 24 小时）。仅本人可读。
  • ~/.config/feishu-backup/token.json：登录令牌，2 小时有效，自动续期。
  • 日志在 ~/Library/Logs/feishu-backup/，保留 30 天。
  • 换电脑：在新 Mac 跑一遍向导；也可以从旧 Mac 拷配置文件，省掉第 2 步。

6.3 调度（Mac 不常开机）

  • 系统定时任务每小时醒一次，程序自己判断要不要跑：
    • 距上次成功不到 24 小时 → 退出
    • 备份盘没插 → 记日志，每天最多提醒一次
    • 没网 → 下个小时再试
    • 已经有一个在跑 → 退出
  • 首次全量可能跨好几次开机：每完成一个文件就记一笔，下次从断点继续。
  • 合盖睡眠打断下载：先写临时文件，下完才改名，不会留下半截文件。

6.4 备份范围

  1. 我的空间：从根目录逐层往下。
  2. 知识库：备份账号能看到的所有空间。带子页面的文档存成 标题.pdf，子页面放进同名文件夹。
  3. 快捷方式：找到它指向的文件；已经在 1、2 里的跳过，否则存在快捷方式所在位置。
  4. 共享给我：群里或搜索发现的、能打开但不在 1–3 里的文档，存到 共享给我/<群名>/，搜索发现的放 共享给我/_搜索发现/。
  5. 群聊附件：所有群里的文件和音视频附件，原格式存到 群聊附件/<群名>/，文件名 日期_原文件名。图片不备份。

6.4.1 去重

  • 同一个文件出现在多处（快捷方式、多个群转发同一个链接）：只存一份，按 我的空间 › 知识库 › 共享给我 的顺序存在第一个位置，其他位置只记录「另见」。
  • 群聊附件按内容判断：内容完全相同的只存一份。
  • 是否有改动：上传文件和附件比较内容，完全相同就不归档、不覆盖；在线文档看飞书的最后修改时间（同一文档每次导出的 PDF 字节可能不同，逐字节比较不可靠）。

6.5 格式规则

飞书类型存成
文档（新版、旧版）PDF
幻灯片PDF
电子表格xlsx（飞书不支持表格导 PDF）
多维表格xlsx
上传的文件、群聊附件原文件原格式，不转换
思维笔记等没有导出接口就跳过，报告里列出

6.6 增量与历史版本

  • 新文件：下载或导出到对应位置。
  • 飞书上改过：先把本地当前版移到同目录 历史版本/，改名为 原名_YYYY-MM-DD_HHMM.扩展名（时间取旧版在飞书上的修改时间，北京时间），再下载新版到原位置。
  • 飞书上改名或移动：本地跟着改名、移动，历史版本一起搬，不算新版本。
  • 飞书上删了，或备份账号没权限了：本地一律不删，在报告里标出。
  • 文件名：非法字符换成 _；同目录重名时加上编号后缀；过长截断，保留扩展名。

版本粒度：版本是每次备份时的快照。两次备份之间改了好几次，只留最后一版。飞书自带的版本记录只含手动保存的版本，靠不上。想要更密，把间隔调短即可。

空间不足：每个文件写入前检查剩余空间，不够就中止这次备份并弹通知，下次从断点续跑。历史版本不设数量上限。

6.7 只读保护

应用开了读写权限，但程序内置白名单，只允许读取类请求：查询、下载、导出、搜索、查元数据、登录续期。其他任何请求在发出前就被拦下，并有测试覆盖。

6.8 权限缺口报告

  • 每次运行扫描所有群的新消息（记住每个群扫到哪里）；首次往回扫 180 天。
  • 找出所有飞书文档链接，逐个判断：能打开 无权限 已删除或无效
  • 输出 _报告/日期_权限缺口.csv，Excel 直接打开。列：状态、类型、链接、文件名线索（消息里的标题）、分享人、群名、分享时间、首次发现日期。
  • 顶部汇总：共发现多少链接，无权限多少，已删除多少。
  • 报告里写明局限：只能发现出现在备份账号所在群里、或者能搜到的文件。

6.9 运行报告

_报告/日期_备份日志.md：耗时，新增、更新、改名、失败、跳过各多少；失败和跳过逐条写原因；列出归档了哪些历史版本。

6.10 限流与重试

  • 每秒最多 5 次请求；导出同时最多 3 个，下载同时最多 4 个。
  • 飞书限流或出错时自动重试 5 次；单个文件失败不影响其他文件，下次再试。
  • 登录失效：停止并弹通知「需要重新登录，对 Claude 说『飞书备份重新登录』」。
§7

留给开发时确认

  • 思维笔记有没有导出接口，没有就跳过。
  • 登录续期令牌能撑多久不开机，向导里如实告知。
  • 搜索接口能覆盖多少「共享给我」的文件。
  • 群消息里文档卡片的标题在哪个字段，用于文件名线索。
  • 过期或撤回附件的报错如何归类。
  • 群聊附件首次体积，向导第 6 步单独估算。
  • 首次全量的耗时估算。
§8

已确认

  • 在线文档存 PDF，表格存 xlsx，上传文件和附件保留原格式
  • 每 24 小时备份一次，版本是每次备份时的快照
  • 「共享给我」的文件一起备份
  • 群聊附件备份到 群聊附件/<群名>/，只要文件和音视频，不要图片
  • 完全相同的文件不重复保存
  • 企业覆盖靠「共享位置为主」，不做员工逐个授权
