# 飞书备份

## 先知道这几件事

- **程序入口**：先确定本 skill 的目录（就是这份 SKILL.md 所在的文件夹，下称 `<base>`），所有命令都是 `python3 <base>/scripts/fbk.py <命令>`。不要假设当前工作目录。
- **Python**：用系统的 `python3`，要求 3.9 或更高，只用标准库，不需要装任何包。如果 `python3` 不存在或版本太低，请用户在「终端」里运行 `xcode-select --install`，装完再继续。
- **说话方式**：用简单的中文，不说 token、scope、LaunchAgent 这类词（必须提到时顺手解释）。**一次只问用户一个问题**，等回答再往下走。
- **App Secret 绝不经过对话**：脚本不能交互输入，凭证只能通过系统弹窗填写。**不要向用户索要 App ID / App Secret，不要让用户贴在对话里，也不要在回复里重复或打印它们。** 如果用户还是把 App Secret 贴进了对话，告诉他：这个 Secret 已经暴露，请到飞书开发者后台「凭证与基础信息」里重置（重新生成）App Secret，然后再走一次弹窗填写。
- 每条命令都可以加 `--json` 拿到机器可读的结果；给用户转述时用中文、去掉技术细节。
- 输出里 ✓ 表示通过，✗ 表示失败，⚠ 表示通过但要提醒。**任何一步出现 ✗：把「怎么办」那一行原样告诉用户，然后停下，等用户处理完再重跑这一步。** 不要自己跳过去。

## 首次配置（用户说「配置飞书备份」）

先运行 `setup --status` 看已经做到第几步（不联网，几秒钟），从第一个没完成的步骤开始。用户需要先在飞书后台建好应用，步骤见插件 README 的「飞书后台准备」；如果用户还没建，先把那部分指给他。

1. **环境检查**：`setup --env`。检查 Python 版本和能不能连上飞书。
2. **应用凭证**：先告诉用户「马上会弹出一个系统对话框，请填 App ID；接着再弹一次填 App Secret（输入不会显示）。对话框可能藏在其他窗口后面，最多等 5 分钟」，然后运行 `setup --credentials`。命令会一直等到用户填完或 5 分钟超时，期间不要催、不要重复运行。
3. **登录授权**：这一步要等用户在浏览器里点「授权」，**必须用 Bash 的 `run_in_background` 在后台运行** `setup --login`。运行后告诉用户：「浏览器会打开飞书授权页，请用要备份的那个飞书账号登录并点『授权』」。等后台命令结束后读结果：显示「已登录：某某」就继续；如果列出了缺少的权限，按「怎么办」让用户去后台补权限、发新版本后重跑这一步。
4. **权限体检**：`doctor`。8 项全部 ✓ 才继续。
5. **备份目录**：问用户「备份放在哪个文件夹？建议放外接硬盘，或者 `~/飞书备份`；首次大约需要几十 GB」。拿到路径后运行 `setup --root <路径>`；目录还不存在、用户也同意新建时加 `--create`。出现 ⚠（例如在 iCloud 同步目录里）要转告用户并问是否换一个。
6. **首次扫描**：`scan`。只统计不下载，文件多时要几分钟到十几分钟，可以放后台运行。把结果用几句话讲给用户：一共多少项、上传文件多少 GB、在线文档估算多少、预计耗时、哪些类型会跳过。然后**明确问用户「确认开始首次备份吗？」，等用户说可以再继续**。用户没确认就停在这里。
7. **定时任务**：`setup --schedule`。告诉用户：电脑开着时每小时检查一次，距上次成功满 24 小时才真正备份；Mac 关机期间不会跑，开机后自动补；备份进行中 Mac 不会因为空闲而睡眠。然后问用户「要不要现在就开始首次备份？」，同意的话**用 `run_in_background` 在后台运行** `run --now`（首次可能要几个小时甚至跨几次开机，中断了下次会接着跑）。

做完告诉用户：以后不用管它；出问题会弹系统通知；想看进度就说「飞书备份状态」。

## 日常命令

| 用户说 | 运行 | 怎么讲给用户 |
|---|---|---|
| 飞书备份状态 | `status` | 上次成功时间、定时任务是否装好、各类文件已备份/失败/跳过多少；最近备份日志和权限缺口报告在哪。 |
| 现在备份一次 | `run --now`（**后台运行**） | 结束时读最后一行「本次结果」，再看最新的备份日志。 |
| 看权限缺口 | `perms` | 共发现多少链接、无权限几个、已删除几个；需要细节时打开 CSV 读给用户。 |
| 飞书备份重新登录 | `login`（**后台运行**，同第 3 步） | 提醒用户去浏览器点授权。 |
| 飞书备份体检 / 备份有问题 | `doctor` | 按 ✓/✗ 表转述，✗ 项原样给「怎么办」。 |
| 卸载飞书备份 | `schedule uninstall` | 说明：只停了定时任务，备份文件一个没删。如果用户还想删掉本机配置，告诉他自己删除 `~/.config/feishu-backup` 文件夹（里面有登录信息）；不要替用户删备份文件夹。 |

## 报告和文件在哪

- `<备份目录>/_报告/YYYY-MM-DD_HHMM_备份日志.md`：每次运行一份，写新增 / 更新 / 改名 / 失败 / 跳过各多少，失败和跳过逐条带原因，归档了哪些历史版本。
- `<备份目录>/_报告/YYYY-MM-DD_权限缺口.csv`：群聊里出现过、但备份账号打不开或已删除的文件链接，带文件名线索、分享人、群名。Excel 可直接打开。
- 目录结构：`我的空间/`、`知识库/<空间名>/`、`共享给我/<群名或 _搜索发现>/`、`群聊附件/<群名>/`。在线文档存成 PDF，表格和多维表格存成 xlsx，上传的文件保持原格式；思维笔记等没有导出接口的类型会跳过，在日志里列出。
- 文件在飞书上被改过，旧版会移到同目录的 `历史版本/原名_日期_时间.扩展名`，**程序从不删除或覆盖本地文件**；飞书上删掉的文件本地也保留。
- `<备份目录>/.feishu-backup/`：清单数据库，换电脑时随备份目录一起拷走即可续上。
- 运行日志：`~/Library/Logs/feishu-backup/`（保留 30 天）。配置：`~/.config/feishu-backup/`（含登录信息，不要发给别人）。

## 排障

`run` 的退出码：

| 退出码 | 意思 | 怎么办 |
|---|---|---|
| 0 | 正常结束；或者还没到时间、已有一次备份在跑、网络不通，安静地跳过了 | 不用处理。用户要求立刻备份就用 `run --now`。 |
| 1 | 运行出错 | 看最新备份日志和 `~/Library/Logs/feishu-backup/` 里当天的日志，找出错原因；必要时跑 `doctor`。 |
| 2 | 还没配置好，或备份目录不存在 | 先 `setup --status` 看缺哪步。目录不存在多半是外接盘没插，请用户插上；插上后定时任务会自动继续。 |
| 3 | 登录过期，需要重新登录 | 后台运行 `login`，让用户去浏览器点授权。Mac 超过 7 天没备份成功，登录就会过期，属正常。 |
| 4 | 备份盘空间不足 | 已备份的部分都保留。请用户清理空间或换更大的盘（换盘后用 `setup --root` 指过去，并把旧目录整个拷过去），然后再 `run --now`。 |

其他常见情况：
- `setup --credentials` 显示「已取消」：用户点了取消、没填、或 5 分钟内没填。问用户准备好了没有，再运行一次。
- 登录时「端口 8765 被占用」：请用户关掉占用的程序或重启电脑后重试。
- 体检里某项 ✗ 并提到「权限」：去飞书开发者后台补对应权限，然后**创建新版本并发布**，再重新登录（`login`）——只加权限不发版、不重新登录都不会生效。
- 「读一条群消息」✗：多半是应用没开机器人能力，见 README。
- **插件更新后**（或换了 Python）：运行一次 `setup --schedule`。定时任务用的是复制到 `~/Library/Application Support/feishu-backup/app/` 的程序副本，重新安装才会换成新版本；`status` / `doctor` 里「定时任务」显示 ✗ 时也是这样修。
